## Método

Lo que aprendimos en la primera ronda (16-oct-2026):
- **Buscar solo en GitHub se queda corto.** Muchas de las mejores piezas son APIs de terceros o servicios: **RapidAPI**, **Apify Store**, APIs públicas como la de freehire, portales oficiales para desarrolladores (idealista, InfoJobs), **PyPI** y **Hugging Face** (modelos y datasets).
- En GitHub, la búsqueda por texto libre da mucho ruido. Funcionan mejor:
  - los *topics* con filtro de estrellas (≥ 20) y actividad (≤ 12 meses);
  - la **búsqueda de código**, que fue la más productiva. Por ejemplo, `gh search code '"boards-api.greenhouse.io" "api.lever.co" "personio" language:python'` encontró maccydee/job-radar y freehire.
- Mirar los **dependientes** de lo que ya usamos, y las listas *awesome*.
- Siempre anotar la **licencia**. AGPL, GPL, PolyForm Noncommercial o sin licencia significan solo lectura.
- Las búsquedas exactas de cada bloque están en su sección, para repetirlas al empezar cada fase.

## Sorpresas y avisos

- **maccydee/job-radar** se llama igual que este proyecto (MIT, 42★), y hay otros tres «JobRadar». Toca decidir si renombramos.
- Hay varios proyectos casi iguales al nuestro: OinkAIJobSearch (Claude + CV + Telegram, licencia no comercial), seancampbell3161/job-aggregator, fedorchenko-juli/job_search_tool, JobNavigator y job-scout. Confirma que la idea tiene sentido; lo que nos diferencia es el nivel empresa, la calidad de las fuentes españolas y el foco en Málaga.
- Están archivados: JobFunnel y `jsonresume/resume-schema`, cuyo esquema ahora vive en jsonresume.org.
- Los términos de EURES prohíben la extracción automatizada para republicar, así que solo sirve para uso personal.
- No hay ningún cliente Python mantenido de la API de ESCO; se usa el CSV.
